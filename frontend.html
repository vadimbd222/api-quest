STAGE 05

Интеграция на фронтенде

Инструмент номер один для работы с API в браузере — функция fetch(). Она есть в каждом современном браузере и возвращает промис с ответом сервера.

Базовый шаблон

async function loadFact() {
  try {
    const res = await fetch('https://catfact.ninja/fact');

    // fetch НЕ бросает ошибку на 404/500 — проверяем сами
    if (!res.ok) throw new Error('HTTP ' + res.status);

    const data = await res.json();
    console.log(data.fact);

  } catch (err) {
    // сюда попадают и сетевые сбои, и наши throw
    console.error('Запрос не удался:', err.message);
  }
}

Что здесь происходит

  1. fetch(url) отправляет GET-запрос и возвращает промис.
  2. res.ok — проверяем статус: всё в диапазоне 200–299?
  3. res.json() читает тело и парсит JSON во второй промис.
  4. try/catch ловит сетевые ошибки (нет интернета, блокировка, CORS).

CORS: почему «чужой» API может не отвечать

Браузеры по умолчанию запрещают странице читать ответы с другого домена. Сервер разрешает это специальным заголовком Access-Control-Allow-Origin. Открытые API (как тот, что мы используем в демо) присылают его всегда; если сервис его не отдаёт — запрос делают через свой серверный прокси.

Состояния загрузки

Пока запрос идёт (он занимает сотни миллисекунд), интерфейс не должен «замереть». Минимальный набор состояний: загрузка (спиннер или прогресс-бар), успех (данные), ошибка (сообщение и кнопка «повторить»). Посмотрите на терминал 7-й стадии — там реализованы все три.
